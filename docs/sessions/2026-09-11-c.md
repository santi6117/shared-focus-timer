## What got built — 6g. Held messages

A small note you leave for the other person that stays **sealed while they're
working**. They see only that something is waiting; the text opens when their
timer ends. Top-left widget, mirrored on both pages.

### The architectural news: this is the app's first cross-write

Every subtree until now has been written only by its owner (§4, "nobody ever
writes into the other person's subtree"). Messages break that on purpose. The
tree is keyed by **recipient**:

```
messages/<recipient>/note : { text, sentAt }   written by the SENDER
messages/<recipient>/read : <sentAt of the message that was read>
                                                written by the RECIPIENT
```

- **Keyed by recipient, not sender**, so each page subscribes to exactly one
  node and reads it whole. Keyed by sender, every page would have to listen to
  the other person's outbox and filter for entries addressed to it — the same
  information with a filter step and a second listener bolted on.
- **Two separate children, not one object with a `readAt` field.** This is
  load-bearing: the rules must let the sender write the text but not the
  receipt, and the recipient write the receipt but not the text. Firebase rules
  apply per path, so two children can be governed separately — two fields of
  one object written with `set()` cannot, and a `set()` carrying both would be
  rejected whole. The code therefore only ever writes
  `messages/<them>/note` and `messages/<me>/read`, never the parent.
- **`read` stores the message's own `sentAt`**, not "when it was read", so
  unread is an exact equality check and nothing depends on comparing two
  machines' clocks.

### Behavior

- **The gate is `timer.running` and nothing else.** Paused, idle, or in the
  count-up all count as readable — a message that could only be opened by
  starting a timer would sit unread forever on a day she never starts one.
- **Chip states:** `✉ Message` (grey) → `✉ message when you're done`
  (terracotta, while sealed) → `✉ 1 message — read it` (terracotta, once the
  session ends). Rendered from the 250ms loop, short-circuiting unless the
  visible state changed — the gate flips in five places (start, pause, reset,
  zero, duration change) and none of them can forget to call it.
- **The read receipt is written when the text is actually on screen** — panel
  open and unsealed — not when the message arrives. A receipt that fired while
  the panel was shut would be a lie, and it's the only signal telling the
  sender whether to expect an answer.
- **Opening at zero is deliberate, not automatic.** The chip changes; she
  clicks. The count-up, the chime and the title flash all fire at that instant
  already.
- **The 6f notification carries it:** if a message is waiting when her session
  ends, the same notification says so on a second line rather than raising a
  second one.

### Decisions made

- **One slot per direction, newest wins**, over a queue. What stops that from
  silently eating a message: the compose box is **prefilled with whatever is
  still pending**, so sending again is visibly editing the thing that's
  waiting. Once it's been read the box clears itself, and the next thing typed
  is a new message.
- **Symmetric — she can send too.** One mirrored rules clause instead of an
  asymmetric one; retrofitting later would mean redoing the rules.
- **Restraint is the feature.** No sound, no title flash, no notification of
  its own, no auto-expand, no animation. A grey envelope turns terracotta and a
  label changes. That is the entire arrival cue.
- **One envelope glyph instead of the presence widget's separate status dot.**
  This chip collapses to icon-only on a phone, where a lone coloured dot says
  "something changed" without saying what.
- **Below 700px the panel floats as an absolute overlay** while the chip stays
  chip-sized, capped at 10.5rem. Widening the widget is the obvious move and is
  wrong — the chip row would grow into the presence pill, and that row is the
  one that must never move. A panel covering the timer for a few seconds is
  fine; two widgets overlapping at rest is not.
- **Widget width is 18rem**, set by the longest label it ever shows
  ("message when you're done") so that string never ellipsises. It's the whole
  feature in four words.

## Security rules — now FIVE clauses, and the first asymmetric one

Still blocked on Kristina's real anonymous UID (§5 item 2). Full ruleset,
ready to paste once both UIDs exist: see `database.rules.pinned.json` in the
repo (added 2026-09-28).

Note that the sealing is a **client-side courtesy, not a security boundary** —
the text is in her browser the moment it's sent, and the rules have to let her
read it in order for her page to display it at all. That's the right trade for
two people who trust each other; it is worth knowing it's not enforced.
