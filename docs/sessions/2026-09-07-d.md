# Session — 2026-09-07 (fourth session)

**Stage:** Milestone 2 §6c — animated background. **Built.** With this, all v1
feature work is complete; only verification remains.

## What got built

The animated background, in two passes. It lives entirely inside the
`#backgroundLayer` element that §6c had already reserved, so nothing else in
the file changed — no JS, no library, no build step.

**Pass 1 — the look.** Eight soft-edged colour blobs (single-hue radial
gradients fading to nothing), heavily overlapped and mostly anchored
off-screen, over a warm base. Two pseudo-elements on the layer: `::before` is a
pale wash over the middle so the timer card sits on calm ground while the edges
keep full colour; `::after` is film grain from an inline SVG turbulence filter.
Built to Santi's reference image at slightly higher saturation.

**Pass 2 — the motion.** Santi's feedback after using it: it moved but cycled
in place, orange never left the left corner. Correct diagnosis — v1 used
`animation-direction: alternate`, which plays a keyframe forward then backward
forever, so each blob could only be a pendulum. Rebuilt so each colour is two
nested elements: an outer `.orbit`, a zero-size point at screen centre that
only rotates, and the `.blob` inside it offset sideways by `--r`. Rotating the
parent carries the blob around a circle; nested transforms compose, so the blob
still runs its own wobble at the same time. Rotation is a closed loop by nature,
so it tours without retracing.

## Decisions made

- **CSS blobs over a canvas flow field or animated SVG turbulence.** Real fluid
  motion is more organic but costs ~150 lines of per-frame JS math; SVG filters
  are the most expensive thing a browser can animate. This page sits open for
  hours.
- **No `filter: blur()` anywhere.** The obvious way to melt blobs together, but
  a fullscreen blur is recomputed every frame while anything moves. Long
  gradient falloffs (solid → transparent across 68% of each blob's radius) give
  the same melted look for free, leaving `transform` as the only animated
  property — GPU-composited, main thread untouched.
- **Gradients end at the same hex with alpha `00`, never at `transparent`.**
  `transparent` is `rgba(0,0,0,0)`, so fading to it drags the ramp through black
  and leaves a grey halo.
- **All eight orbits share one path, differing only in start angle** (set by
  negative `animation-delay`), with the blobs threaded on in **spectral order**.
  This is what stops the tour from turning to mud: the colour wheel is mapped
  onto the circle, so hue neighbours stay adjacent and complements stay half a
  lap apart. Complements overlapping at equal strength average to grey, so
  letting eight colours roam freely would have silted up within a minute.
  **Reshuffling `.b1`–`.b8` is the one edit that breaks this.**
- **The cool half laps 18% slower**, so the two halves slide against each other
  over minutes rather than rotating as one rigid body. Sole source of warm-on-cool
  overlap, and because it's always sliding, muddiness is transient.
- **Radii vary 24–46vmax.** Eight blobs at one radius reads as a spinning ring —
  mechanical. Uneven radii make it a swarm that happens to circulate.
- **Two independent time knobs, not one.** `--bg-cycle` is local churn,
  `--bg-tour` is lap time. Churning fast while travelling slowly is a completely
  different feel from the reverse, and one number couldn't express both.
- **`linear` timing on the lap.** Easing would make the whole wheel visibly
  speed up and slow down once per lap, reading as a machine cycling.
- **Film grain is functional, not decorative.** A gradient covering a whole
  screen has so few distinct colours per inch that 8-bit panels render the
  blends as visible stripes; the speckle breaks them up.
- **`prefers-reduced-motion` freezes both layers** into a still gradient.
- **Rejected during pass 1:** a first colour pass came out muddy lavender
  because warm and cool blobs were fighting over the middle. Fixed by splitting
  warm-left / cool-right — the ancestor of pass 2's spectral ordering.

## State of the code

`index.html` complete and brace-balanced. Verified by rendering the real file in
headless Chromium at multiple animation phases and inspecting the frames: the
composition genuinely relocates across a lap, with no bald patches and no
muddying. **Santi confirmed it in his own browser** and tuned `--bg-cycle` to
`30s` — the first real-browser look at this file since 2026-09-05.

Backups: `index-pre-background-backup.html` (before pass 1),
`index-pre-orbit-backup.html` (before pass 2).

Cost note: eight composited layers. The `.orbit` wrappers are 0×0 and paint
nothing, so pass 2 doubled the DOM nodes but not the layer count. On older
integrated graphics this could warm a fan over a long session; deleting `.b3`
and `.b8` drops it to six with little visual loss.
